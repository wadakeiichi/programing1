### なぜ C を学ぶのか

Python は書きやすく読みやすい言語で、科学計算の主力になっている。一方 C 言語は、

- **速い**（数値計算の重い部分は C で書かれていることが多い。NumPy の内部も C）
- **ハードウェアに近い**（メモリを直接扱う。OS や組み込み機器の開発に使われる）
- **多くの言語の祖先**（C の文法は Python・Java・JavaScript などに影響を与えた）

という特徴を持つ。Python で身につけた「変数・条件分岐・ループ・配列・ファイル入出力」という考え方は **そのまま C にも通じる**。違うのは主に **書き方（文法）と、実行の仕組み** である。

---

### コンパイルとは ― Python との最大の違い

いちばん大きな違いは **プログラムの実行のされ方** である。

- **Python はインタプリタ型**: 書いたコードを **その場で 1 行ずつ解釈しながら実行** する。`python hello.py` とすればすぐ動く。
- **C はコンパイル型**: 書いたソースコード（人間が読む文字）を、**コンパイラ** がいったん **機械語（CPU が直接実行できる形）に翻訳** してから実行する。この翻訳作業を **コンパイル（compile）** と呼ぶ。

図にすると次のような違いになる。

| | Python（インタプリタ） | C（コンパイル） |
|---|----------------------|----------------|
| 手順 | `hello.py` を書く → `python hello.py` で即実行 | `hello.c` を書く → **コンパイル** → 実行ファイル → 実行 |
| 翻訳のタイミング | 実行するたびに解釈 | 実行前に一度だけ機械語へ翻訳 |
| 速度 | 比較的ゆっくり | 速い（翻訳済みを直接実行） |
| エラー | 実行して初めて分かることが多い | **コンパイル時** に多くの誤りが分かる |

> **ポイント**: C では「コンパイルが通る（＝機械語に翻訳できる）」ことが第一関門。文法の誤りはコンパイル時にエラーとして指摘されるので、**まずコンパイルを通す** ことを目指す。

### dev container での C の実行方法

C のコンパイルには **`gcc`**（GNU C コンパイラ）を使う。手順は「① ソースを書く → ② `gcc` でコンパイル → ③ できた実行ファイルを走らせる」の 3 段階。

まず、VS Code で `week14_c/hello.c` というファイルを作り、次を書く。

```c
#include <stdio.h>

int main(void) {
    printf("Hello, C world!\n");
    return 0;
}
```

VS Code の **ターミナル** で、`week14_c` フォルダに移動してコンパイル・実行する。

```bash
cd week14_c
gcc hello.c -o hello    # hello.c をコンパイルして実行ファイル hello を作る
./hello                 # できた実行ファイルを実行する
```

- **`gcc hello.c -o hello`**: `hello.c` をコンパイルし、`-o hello` で **実行ファイルの名前を `hello`** にする。
- **`./hello`**: カレントフォルダ（`./`）にある実行ファイル `hello` を実行する。
- 画面に `Hello, C world!` と出れば成功。

> Python なら `python hello.py` の 1 コマンドだが、C は **コンパイル（`gcc ...`）と実行（`./hello`）の 2 段階** になる。ソースを直したら、**もう一度コンパイルし直す** 必要がある点に注意。

### 基本文法 ― Hello, World を読み解く

さきほどの `hello.c` を Python と比べながら読む。

```python
# Python
print("Hello, C world!")
```

```c
/* C */
#include <stdio.h>          /* 標準入出力の機能を取り込む（printf を使うため） */

int main(void) {            /* main：プログラムの入口。必ず必要 */
    printf("Hello, C world!\n");   /* 文字列を表示。\n は改行 */
    return 0;               /* 0 を返して正常終了を知らせる */
}
```

Python との違いがいくつもある。

- **`#include <stdio.h>`**: `printf` などの機能を使うために必要な「取り込み宣言」。Python の `import` に近い。
- **`int main(void) { ... }`**: C のプログラムは必ず **`main` 関数から始まる**。Python のように「上から順に」ではなく、**`main` の中身が実行される**。
- **文の終わりに `;`（セミコロン）**: C では **1 文ごとに必ずセミコロン** を付ける。Python は改行で文が区切られたが、C は `;` で区切る。
- **ブロックは `{ }`（波かっこ）**: Python は **インデント** でブロックを表したが、C は **`{ }`** で囲む（インデントは見やすさのためで、文法上は必須ではない）。
- **`\n`**: 改行文字。C の `printf` は自動で改行しないので、改行したいときは自分で `\n` を入れる。
- **`return 0;`**: `main` が 0 を返すと「正常終了」の意味。
- **コメント**: `/* ... */` で囲んだ部分は **コメント**（人へのメモ書き）で、コンパイラには無視される。Python の `#` に相当する。上のコードの `/* main：プログラムの入口 */` などがそれ。

#### コメントの書き方 ― `/* */` と `//`

Python では `#` から行末までがコメントだった。C では **2 通り** の書き方がある。

```python
# Python：# から行末までがコメント
x = 10   # これはコメント
```

```c
/* C：2 種類のコメント */
int x = 10;   // この行の末尾まで（1 行コメント）
int y = 20;   /* こちらは範囲コメント。
                 複数行にまたがって書ける */
```

- **`// ...`**: その **行の末尾まで** がコメント（Python の `#` と同じ感覚）。
- **`/* ... */`**: `/*` から `*/` までがコメント。**複数行にまたがって** 書ける。
- コメントはコンパイル時に無視されるので、動作には影響しない。**なぜその処理をするのか** をメモしておくと、後で読み返したときに分かりやすい（Week 3b で学んだコメントの心得と同じ）。

> **注意**: `/* */` は **入れ子（ネスト）にできない**。`/* 外 /* 内 */ 外 */` と書くと、最初の `*/` でコメントが終わってしまい、残りがエラーになる。コードの一部をまとめて無効化したいときは注意すること。

> **ポイント**: Python の「インデントでブロック」「改行で文の区切り」に対し、C は **「`{ }` でブロック」「`;` で文の区切り」**。この 2 つが最初に慣れるべき違い。

#### `{ }` の意味とインデント ― C はインデントを見ない

**`{ }`（波かっこ、ブレース）は「ここからここまでを 1 つのまとまり（ブロック）とする」印** である。C のコンパイラは、`if` や `for`、`main` などが従える「一続きの処理」を、**インデント（字下げ）ではなく `{ }` の範囲で判断** する。

ここが Python との決定的な違い。**Python はインデントそのものが文法**（字下げがずれると別のブロックになったりエラーになる）だったが、**C はインデントを完全に無視する**。空白や改行は人間の見やすさのためだけにあり、コンパイラは `{ }` と `;` だけを見ている。

そのため、次の 3 つは C ではすべて **まったく同じ意味** になる（どれも正しくコンパイル・実行できる）。

```c
/* 見やすく書いた（推奨） */
#include <stdio.h>

int main(void) {
    int x = 5;
    if (x > 0) {
        printf("positive\n");
    }
    return 0;
}
```

```c
/* インデントがめちゃくちゃでも同じ意味（コンパイルは通る） */
#include <stdio.h>
int main(void){
int x = 5;
if(x>0){
printf("positive\n");
}
return 0;}
```

```c
/* 極端な例：1 行に詰めても同じ（{ } と ; で区切られているため） */
#include <stdio.h>
int main(void){ int x = 5; if(x>0){ printf("positive\n"); } return 0; }
```

3 つとも別々のファイルに保存してコンパイルすれば、**すべて `positive` と表示される**（例：`gcc indent1.c -o indent1` → `./indent1`）。見た目が全く違うのに結果が同じ、という点を自分の目で確かめること。

> **とはいえ必ずインデントすること**: コンパイラは気にしなくても、**人間には読めない** コードは間違いのもと。`{ }` の中は字下げする、というルールは Python と同じく守ること。「文法上は不要だが、書き方の作法としては必須」と考える。

##### `{ }` を省くと落とし穴 ― 波かっこ 1 つ分しか従えない

`if` や `for` は、`{ }` を付けない場合 **直後の 1 文だけ** を従える。インデントは無視されるので、字下げした複数行が全部 `if` に入っている「つもり」でも、実際には最初の 1 文しか条件に含まれない。

```c
/* 危険な例：{ } を付けていない（実際に動かして確かめること） */
#include <stdio.h>

int main(void) {
    int x = -3;            /* x は負。だから "A" は表示されないはず… */
    if (x > 0)
        printf("A\n");     /* ← この 1 文だけが if に従う */
        printf("B\n");     /* ← インデントされているが if の外。常に実行される！ */
    return 0;
}
```

これをコンパイルして実行すると、`x` が負なのに **`B` だけが表示される**（`A` は出ない）。`printf("B\n");` は、見た目のインデントに反して **x の値に関係なく必ず実行される** からである。これは初学者が非常にはまりやすいバグ。**`if`・`for`・`while` の中身は、1 文でも必ず `{ }` で囲む** 習慣をつけると、この落とし穴を避けられる。

### 変数と型 ― 型を必ず宣言する

#### 型（type）とは何か

**型とは「そのデータが何の仲間か（データの種類）」** のこと。具体的には、次の 2 つを決める。

- そのデータを **メモリ上でどう表現し、何バイト使うか**（整数なのか小数なのか、扱える大きさはどれくらいか）
- そのデータに **どんな操作ができるか**（数なら四則演算ができる、文字は文字として扱う、など）

Python は、変数に値を入れた瞬間に **実行時に型を自動で判定** していた（動的型付け）。だから同じ変数に整数を入れたり文字列を入れたりできた。一方 C は **コンパイル時に型を固定** する（静的型付け）。「この変数は整数（`int`）です」と **先に宣言** しておく必要があり、コンパイラはその型を見て「メモリを何バイト確保するか」「`+` をどんな計算にするか」を決める。**型は、コンピュータがデータをどう扱うかを決める設計図** だと考えるとよい。

Python では `x = 3` と書けば型は自動で決まった。C では **変数を使う前に「型」を宣言** する必要がある。

```python
# Python：型を書かない
n = 10
pi = 3.14
c = 'A'
```

```c
/* C：型を必ず宣言する */
int n = 10;          /* 整数 */
double pi = 3.14;    /* 浮動小数点数（Python の float に相当） */
char c = 'A';        /* 1 文字 */
```

主な型は次の通り。

| 型 | 意味 | Python の対応 |
|----|------|--------------|
| `int` | 整数 | `int` |
| `double` | 小数（倍精度） | `float` |
| `char` | 1 文字 | 長さ 1 の `str` |

#### 型による計算の違い ― 整数どうしの割り算

C では **型によって計算結果が変わる** ことがある。とくに割り算は要注意。

```c
int a = 7, b = 2;
printf("%d\n", a / b);      /* 3 ← int どうしの割り算は「整数の割り算」＝小数点以下は切り捨て */
printf("%f\n", 7.0 / 2);    /* 3.500000 ← 片方でも double なら小数の割り算になる */
```

Python 3 では `7 / 2` は `3.5`、`7 // 2` が `3` だった。**C の `int / int` は Python の `//` に近い**（結果も `int` になり、小数点以下は捨てられる）。小数の答えがほしいときは、`7.0 / 2` のように **どちらかを `double` にする**。「同じ `7 ÷ 2` でも、関わる値の型で答えが変わる」――これが型を意識すべき典型例。

#### printf の書式 ― 値を埋め込んで表示する

`printf` で変数の値を表示するには、**書式指定子** を使う（Python の f-string に相当）。

```python
# Python
n = 10
pi = 3.14159
print(f"n = {n}, pi = {pi:.2f}")
```

```c
/* C */
int n = 10;
double pi = 3.14159;
printf("n = %d, pi = %.2f\n", n, pi);
```

- **`%d`**: 整数（`int`）を埋め込む。
- **`%f`**: 小数（`double`）を埋め込む。`%.2f` で小数第 2 位まで。
- **`%c`**: 1 文字（`char`）。
- 埋め込む値は **`,` の後ろに順番に並べる**。

### if 文 ― 条件分岐

考え方は Python と同じ。違いは **条件を `( )` で囲む**・**ブロックを `{ }` で囲む**・**`elif` ではなく `else if`** という点。

```python
# Python
score = 75
if score >= 80:
    print("A")
elif score >= 60:
    print("B")
else:
    print("C")
```

```c
/* C */
int score = 75;
if (score >= 80) {
    printf("A\n");
} else if (score >= 60) {
    printf("B\n");
} else {
    printf("C\n");
}
```

比較演算子（`==`, `!=`, `<`, `>=` など）は Python とほぼ同じ。ただし論理演算子は **`and`/`or`/`not` ではなく `&&`/`||`/`!`** を使う。

```c
int score = 75;
if (score >= 60 && score < 80) {
    printf("B の範囲\n");
}
```

### ループ ― for と while

繰り返しも考え方は同じだが、**for の書き方が大きく違う**。C の `for` は「**初期化; 継続条件; 更新**」の 3 つを `;` で区切って書く。

```python
# Python：0,1,2,3,4 を表示
for i in range(5):
    print(i)
```

```c
/* C：0,1,2,3,4 を表示 */
for (int i = 0; i < 5; i++) {
    printf("%d\n", i);
}
```

- **`int i = 0`**: 初期化（最初に 1 回だけ）。
- **`i < 5`**: 継続条件（これが真の間くり返す）。
- **`i++`**: 更新（毎回の最後に実行。`i++` は `i = i + 1` の意味）。

`while` は Python とほぼ同じ形。

```python
# Python
i = 0
while i < 5:
    print(i)
    i += 1
```

```c
/* C */
int i = 0;
while (i < 5) {
    printf("%d\n", i);
    i++;
}
```

### 例 ― 1 から N までの合計を求める

Python と C で同じ計算（1 + 2 + ... + N）を書き比べる。**変数の型宣言・`for` の書き方・`printf` の書式** に注目。

```python
# Python
N = 10
total = 0
for i in range(1, N + 1):
    total += i
print(f"1 から {N} までの合計 = {total}")
```

```c
/* week14_c/sum.c */
#include <stdio.h>

int main(void) {
    int N = 10;
    int total = 0;
    for (int i = 1; i <= N; i++) {
        total += i;              /* total = total + i と同じ */
    }
    printf("1 から %d までの合計 = %d\n", N, total);
    return 0;
}
```

コンパイルして実行する。

```bash
gcc sum.c -o sum
./sum
```

**実行結果の確認ポイント**: `1 から 10 までの合計 = 55` と表示されれば成功。Python 版と同じ結果になること、C では `int` の型宣言と `for (i=1; i<=N; i++)` の形になっている点を確認する。

### 例 ― Python と C で実行時間を比べる

「C は速い」を実際に体感する。**1 億回の足し算**（1 + 1/2 + 1/3 + ... + 1/N, N = 1 億）という同じ計算を Python と C で書き、実行時間を比べる。計算結果はどちらも同じ（約 18.9979）になるが、**かかる時間が大きく違う**。

```python
# time_loop.py
N = 100_000_000
s = 0.0
for i in range(1, N + 1):
    s += 1.0 / i
print(s)
```

```c
/* week14_c/time_loop.c */
#include <stdio.h>

int main(void) {
    long N = 100000000L;      /* 1 億。大きい値なので long 型にする */
    double s = 0.0;
    for (long i = 1; i <= N; i++) {
        s += 1.0 / (double)i;
    }
    printf("%.10f\n", s);
    return 0;
}
```

**VS Code のターミナル** で、`time` コマンドを付けて実行すると、かかった時間が測れる。

```bash
# Python（そのまま実行）
time python time_loop.py

# C（コンパイルしてから実行）
gcc time_loop.c -o time_loop
time ./time_loop
```

`time` の出力のうち **`real`（実際の経過時間）** を見る。目安は次の通り（環境によって変わるが、比は大きく変わらない）。

| 実行方法 | 時間の目安 | Python との比 |
|---------|-----------|--------------|
| Python | 約 5〜6 秒 | 1 倍（基準） |
| C（`gcc time_loop.c -o time_loop`） | 約 0.3〜0.4 秒 | **十数倍速い** |
| C（`gcc -O2 time_loop.c -o time_loop`） | 約 0.1 秒 | **数十倍速い** |

- **`-O2`** は gcc の **最適化オプション**。付けるとコンパイラがコードを速くなるよう工夫してくれる（`gcc -O2 ...` のように付けるだけ）。

**実行結果の確認ポイント**: 結果の数値は Python も C も同じなのに、**C の方が圧倒的に速い** ことが `time` の `real` から読み取れれば成功。これが「重い数値計算は C（や C で書かれた NumPy）で行う」理由である。一方で、Python は書きやすく試しやすいという利点があり、**速度が必要な部分だけ C に任せる** という使い分けがよく行われる。

> **補足**: Python が遅いのは「1 行ずつ解釈しながら実行する」ため。とくに **大きな `for` ループ** で差が出る。Python でも、ループを NumPy のベクトル演算（Week 5）に置き換えると大幅に速くなる（内部が C で書かれているため）。

### 補講課題 1（任意・提出不要）

理解の確認用。提出は不要だが、実際にコンパイル・実行して動かしてみること。

1. **偶数の表示**: 1 から 20 までの整数のうち **偶数だけ** を表示する C プログラム `even.c` を書け（`if (i % 2 == 0)` を使う）。`gcc even.c -o even` でコンパイルし、`./even` で実行して確認せよ。

2. **九九の一部**: `for` を使って、3 の段（3, 6, 9, ..., 27）を表示する C プログラム `kuku.c` を書け。同じ処理を Python でも書き、**書き方の違い**（型宣言・`{ }`・`;`・`printf` の `%d`）をコメントで説明せよ。
